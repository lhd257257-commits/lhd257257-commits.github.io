## 4. 网站实现

### 4.1 技术

- 原生 HTML + CSS + Canvas 2D；
- 无框架、无构建、无 npm 运行依赖；
- 静态服务器 `serve.mjs`（4178）；
- `atlas.json` 与 `deaths.json` 本地加载；
- 死亡数据**懒加载**：只有点击“死亡热区”才请求 3.1MB JSON。

### 4.2 地图

- 不使用 PUBG 官方地图、Logo、音乐或角色素材；
- 底图是原创示意地图，保留 0—1000 坐标、网格、抽象地形和 A1—J10 分区；
- 明确标注 `SCHEMATIC MAP · NOT OFFICIAL`。

### 4.3 热区算法

1. 数据先按 40×40 像素分箱（地图画布 1000×1000）；
2. 权重做平方根式压缩，避免极值压扁其他区域；
3. 用径向渐变绘制热区；
4. 对高权重单元叠加“热核”，保留尖峰；
5. 颜色从青绿 → 金 → 橙 → 红；
6. 自动计算 10×10 扇区聚合与 TOP 5。

### 4.4 页面设计

- 深色战术仪表盘，避免 PUBG 官方视觉；
- 三栏桌面布局：控制 / 地图 / 读数；
- 移动端改为地图优先，筛选和说明在下方；
- 加载失败会提示“死亡数据未生成”，不影响圈层/红区页面。

## 8. 已知限制

- 死亡热区是 **100×100 网格**，不是逐点热图；
- 死因是关键词分类，不是官方分类；
- 没有队伍、模式、玩家排名、单场筛选；
- 2018 年数据，版本过时，样本有低分段种子偏差；
- 地图为示意，不能用于精确报点；
- 没有后端/数据库/实时 API；
- E 盘曾掉盘，原始 CSV 的可持续可用性依赖 E 盘状态；站点只依赖已生成的 `deaths.json`。
