# 01 数据与图表说明

## 1. 页面在回答什么

Tactical Atlas 不回答“下一局哪里最安全”，而是回答：

- 历史上，首圈中心更常落在哪些区域？
- 决赛圈中心在坐标空间里如何分布？
- 红区落点在哪些区域更频繁？
- 这些区域在 10×10 分区中如何排序？

## 2. 数据表

| 图层 | 来源表 | 含义 | 行数 |
|---|---|---|---:|
| 首圈中心 | `first_circle` | 首圈中心落点的聚合计数 | 15,030 |
| 决赛圈 | `zc_lastpoisoncircle` | 最后毒圈中心落点的聚合计数 | 2,000 |
| 红区 | `zk_redzone` | 红区落点的聚合计数 | 2,063 |

字段：`x`、`y`、`n/numble`、`map`。坐标范围 0—1000。

页面不展示具体玩家、账号或单场对局，只展示聚合网格。

## 3. 热区算法

1. 把原始 0—1000 网格按 **40×40** 分箱；
2. 每个分箱按权重求质心；
3. 权重经 `n^0.42` 压缩，避免极值完全压扁其他区域；
4. 用径向渐变绘制到 1000×1000 Canvas；
5. 对峰值单元叠加“热核”，保留尖峰；
6. 颜色从青绿 → 金 → 橙 → 红。

图例写“SQRT WEIGHTED”表示压缩后的权重显示，不是原始绝对人数。

## 4. 如何读图

- 热区是**聚合频率**，不是因果结论；
- “首圈中心”不等于玩家落点；
- “决赛圈”样本远少于首圈，区域差异不能直接当规律；
- 红区是随机事件，历史高频不等于下一局必炸；
- 分区编号（A1—J10）用于定位，底图为原创示意，不是官方地图。

## 5. 死亡热区（已接入完整数据）

完整 Kaggle 数据已下载并处理：4.4GB zip，5 个死亡 CSV 约 9.75GB，聚合权重 **64,586,279**。

处理方式：

1. DuckDB 分块读取 5 个 `kill_match_stats_final_*.csv`；
2. 过滤 `ERANGEL` / `MIRAMAR`、坐标 0—799999；
3. 按 `map × phase × cause × 100×100 网格` 聚合；
4. 输出 `data/deaths.json`（约 3.1MB）；
5. 页面点击“死亡热区”时懒加载，不拖慢圈层页。

死因分类是关键词分类：

- 步枪：M416/AKM/SCAR/UMP/Vector/Beryl/M762/Groza/AUG/QBZ/DP28/M249 等；
- 狙击：AWM/Kar98/M24/SKS/Mini14/Mk14/Win94 等；
- 霰弹/近战：S686/S1897/S12K 等；
- 载具、毒圈/环境、其他。

这不是官方武器分类，也不包含队伍/模式/排名过滤；需要原始明细的更多维度时要重新聚合。

## 6. 为什么不做逐点热图

65M 个死亡点如果全部传到浏览器，体积与渲染都会不可接受。因此使用 100×100 网格（每格 10×10 坐标单位），既保留区域差异，也能在静态站点里快速加载。

如果需要精确到单点，应该做服务端查询或矢量瓦片；当前版本不做。
